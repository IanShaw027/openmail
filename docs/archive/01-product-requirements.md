# 01 · 产品需求

## 1. 目标

在**自有服务器**上提供 Web 服务，让用户：

1. 批量管理多类型邮箱账号  
2. 快速取信并提取验证码  
3. 最少点击完成复制与对接  
4. 为账号签发**收码 API URL**，供自动化脚本调用  

## 2. 目标用户

- 需要批量收 OTP / 验证码的运营、开发、号池维护者  
- 同时持有微软 OAuth 号、mail.com 类网页邮、IMAP 授权码号、CF 自建邮的人  

## 3. 成功标准

| 场景 | 成功表现 |
|------|----------|
| 导入 | 粘贴多行 → 一次导入成功，自动识别类型 |
| 取验证码 | 点账号行后，最新验证码可见且一键复制 |
| 批量 | 勾选或本页批量拉取，并发可控 |
| 收码 API | 一点生成 URL，外部请求返回约定格式验证码 |
| Cookie 邮 | 二次取信优先走 cookies，不每次全量登录 |
| 隐私可读 | 页面有明确留存说明；删号可清凭证 |

## 4. 功能需求

### 4.1 账号管理

- [ ] 文本导入 / TXT 导入  
- [ ] 导出选中或全部（导入兼容格式）  
- [ ] 列表：邮箱、类型、标签、最新验证码、状态、操作  
- [ ] 编辑：凭证字段、标签、备注  
- [ ] 删除选中；清空（需确认）  
- [ ] 搜索：邮箱 / 标签 / 备注；按类型、状态筛选  
- [ ] 分页  

### 4.2 取信

- [ ] 单账号拉取（收件箱 / 垃圾箱，若 Provider 支持）  
- [ ] 快速取件 vs 全部/更深拉取（超时与数量策略可配）  
- [ ] 批量拉取（有限并发）  
- [ ] 邮件列表 + 详情预览  
- [ ] 服务端解析 `verification_code`  
- [ ] 邮件搜索：主题 / 发件人 / 验证码  

### 4.3 快捷操作（少操作优先）

主路径目标操作次数：

| 动作 | 目标 |
|------|------|
| 导入一批 | 粘贴 → 导入（1 次） |
| 看最新码 | 点行即展示 |
| 复制验证码 | **1 次点击** |
| 复制邮箱 | 1 次点击 |
| 复制收码 API URL | 1 次点击（生成或展示后复制） |
| 批量刷新 | 1 次点击 |

信息优先级（UI）：

1. 最新验证码（最大、可点复制）  
2. 邮箱地址  
3. 状态（可取信 / 会话失效 / OAuth 异常 / 无凭证）  
4. 密码、token、cookies 等（编辑区，不挡主视线）  

### 4.4 收码 API

- [ ] 用户在 Web 对某账号点击「API 取件 / 生成接口」  
- [ ] 后端返回（或展示）**专用 API URL**  
- [ ] 外部对该 URL 发起请求 → 后端用**已存凭证**取信 → 返回验证码  
- [ ] 支持多种返回格式（见 [05-code-api.md](05-code-api.md)）  
- [ ] 支持重置 URL（旧 token 立即失效）  
- [ ] 可选：关键词 / 正则过滤  

### 4.5 Provider 覆盖（需求级）

| Provider | 优先级 | 说明 |
|----------|--------|------|
| oauth（微软 Graph） | P0 | `email----password----refresh_token----client_id` |
| cookie（mail.com 等） | P0 | 存 password + cookies |
| http_api（CF 等） | P0 | 存 api_url |
| imap | P0/P1 | 服务端 IMAP；导入需 host 或域名推断 |
| 其他网页邮 cookie 插件 | P2 | 同一 cookie Provider 框架扩展 |

## 5. 非功能需求

- **安全**：管理密码保护管理接口与破坏性操作；收码 token 高熵；凭证 at-rest **必须**加密；HttpApi **必须** SSRF 防护  
- **收码权限**：游客仅 create-or-return；rotate 需管理员或 current_token；delete 仅管理员（见 09/10）  
- **工程底线（防打爆上游）**：短缓存优先、同账号串行、最小 fetch 间隔、批量有限并发；**运营配额类限流**可后续  
- **可观测**：last_error、last_fetch_at；日志禁止明文密码/token/cookies  
- **可删除**：删服务端账号（管理员）级联清凭证、会话、邮件缓存、API 映射  

## 6. 明确不做（MVP）

- 完整邮件客户端（多级文件夹、标签体系、大附件）  
- 默认公网匿名「把任意 token 贴上来就取」（可另做可选临时模式，默认关）  
- 把用户邮件用于任何二次用途  
- 保证绕过所有邮箱风控 / 2FA 人机验证（能力边界写进文档）  

## 7. 交互原则

1. **重要信息少操作**：验证码与 API URL 永远在 1 次点击内  
2. **类型自动识别**：导入尽量不让用户选手动 Provider  
3. **失败可读**：OAuth 过期、cookies 失效、IMAP 拒识用短中文错误  
4. **隐私可预期**：导入与生成 API 时展示留存说明摘要
