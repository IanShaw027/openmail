# 09 · 已决议（产品共识）

> 更新：2026-08-01  
> 本文覆盖此前未决项；与旧文档冲突时 **以本文为准**。

## 1. 部署与用户模型

| 项 | 决议 |
|----|------|
| 部署 | **单实例自托管** |
| 角色 | **管理员** + **注册用户（User）** + **游客（Guest）** |
| 游客 | 免登录：本机缓存、公开号池、取件、收码；**禁止**用户邮件库与邮件搜索 |
| 注册用户 | **开放注册 + 登录**（无邀请码/无审批）；对 **本人数据** 完整权限；须同意隐私与使用政策 |
| 管理员 | 管理密码：系统配置、代理池/sid、同步周期、用户启停、清库等（**无**邀请码/审批策略） |
| 多用户 | 非 SaaS 多租户产品，但 **按 owner_user_id 隔离用户数据** |

### 能力边界（三层）

| 能力 | 游客 | 注册用户（本人数据） | 管理员 |
|------|------|----------------------|--------|
| 本机缓存、公开号池、取信 | ✅ | ✅ | ✅ |
| 收码（公开号 / 规则内） | 见 10 | 对自己的号 **完整** | ✅ |
| **注册 / 登录** | ❌ | ✅ | 管理端另计 |
| **自己的邮箱 CRUD / 同步 / 导出** | ❌ | ✅ **完整** | 可运维 |
| **自己的邮件搜索** | **❌ 禁止** | ✅ **完整** | 可跨用户运维 |
| 实例 sid 代理池、同步间隔 | ❌ | ❌ | ✅ |
| 用户管理 / 清库 | ❌ | ❌ | ✅ |

> **公开号池 public**：实例内共享（旧模型）。  
> **用户私有池**：`owner_user_id` 隔离；「我的邮件」只搜自己的索引。  
> **游客永远不能搜邮**（无配置开关放开）。  
> 详见 [12-trusted-pool-and-mail-sync.md](12-trusted-pool-and-mail-sync.md)。
## 2. 双存储模型（核心）

| 凭证是否在服务端保存 | 账号列表与凭证 | 取件时 |
|----------------------|----------------|--------|
| **已入库** | 服务端加密存储 | 服务端读库取信，结果可回写缓存 |
| **未入库** | **仅浏览器缓存**（localStorage/IndexedDB） | 客户端把本次取信所需字段提交给服务端**代理取信**；默认不落库（除非用户显式「保存到服务器」） |

- **收码 API**：仅当账号**已在服务端有记录**且已生成 token 时可用（一对一绑定服务端记录）。  
- 纯浏览器缓存账号：可 Web 取件，但**不能**签发长期收码 URL（或仅支持「先保存到服务器再生成 API」）。

## 3. 凭证来源（禁止平台托管授权）

| 项 | 决议 |
|----|------|
| 平台 OAuth 授权页 / 托管 client 代用户授权 | **不做** |
| 所有 OAuth | 用户**自行提供** `client_id` + `refresh_token`（及兼容字段） |
| Cookie / 密码 / IMAP / api_url | 全部由**用户端导入或填写** |
| 服务端 | 只存储与使用用户给出的数据，不代替用户完成厂商授权流程 |

## 4. 加密

- 服务端保存的敏感字段（password、refresh_token、cookies、imap 密码、api 中的密钥等）**必须 at-rest 加密**。  
- 主密钥来自部署环境变量（如 `OPENMAIL_MASTER_KEY`）。  
- 日志禁止明文密钥。

## 5. 收码 API

| 项 | 决议 |
|----|------|
| 绑定 | **一条账号记录 ↔ 一个 API token**（一对一） |
| 生成时机 | 用户对某条记录点击生成 API 时，服务端生成**唯一 token** |
| 客户端 | **浏览器缓存同步更新**该账号的 `code_api_url` / token 展示字段 |
| 调用方式 | **仅 URL**；**GET 与 POST 均支持** |
| Header 鉴权 | **不需要**（token 在 URL 路径或 query 中） |
| 限流 | **运营限流暂不做**；**工程底线必须做**（短缓存、串行、最小间隔，见 §8） |
| 格式 | 仍支持 text / json / nullx 等（见 05） |

示例：

```http
GET  /api/v1/code/{token}
POST /api/v1/code/{token}
GET  /api/v1/code/{token}?format=text&keyword=ChatGPT
POST /api/v1/code/{token}   body: {"format":"json","regex":"\\d{6}"}
```

## 6. Cookie 会话策略（对齐 mail.com.helper 并加强「自动续期」）

### 6.1 参考项目 mail.com.helper 实际行为

源码结论（`start.py`）：

1. **磁盘会话缓存**：`cache/sessions/{hash}.json`，内存 cookies + `saved_at_ts`。  
2. **硬过期**：`SESSION_MAX_AGE_SECONDS = 6 * 60 * 60`（6 小时）。超过则**直接删文件**，不再尝试用旧 cookies。  
3. **命中缓存**：加载 cookies → 请求 lightmailer 文件夹页 → 若含 `FolderListPage` 则视为有效，并 **立刻 `save` 写回**（刷新磁盘时间戳与 cookie 内容）。  
4. **每次成功 `_request` 后**：再次 `session_cache.save(..., source="refresh")`，即 **滚动更新 cookies**。  
5. **中途掉登录**：`_looks_like_session_loss` → 清缓存 → **`force` 全量密码登录** → GET 可重放一次；非 GET 抛 `SessionRenewedError` 让上层重试。  
6. **无密码且会话失效**：报错，要求用户重新导入密码。

因此 helper **已经在做「用则续写 cookies」**，但同时有 **6 小时硬丢弃**，且失效后的恢复路径是 **密码重登**，不是某种独立的 refresh_token。

### 6.2 OpenMail 决议（比 helper 更偏向「尽量自动续期」）

| 策略 | OpenMail |
|------|----------|
| 每次成功取信/探测 | **写回最新 cookies**（滚动续期，与 helper 一致） |
| 硬过期 | **不以固定 6h 删除仍可用的 cookies**；以**探测是否仍登录**为准 |
| 可选上限 | 可配置「绝对最大龄」（如 7 天）防止无限堆积；默认应远大于 6h 或关闭硬删 |
| 后台/顺带续期 | 取信成功即续；可选对将过期账号做轻量 head/folder 探测以刷新（P1） |
| 密码重登 | **仅当 cookies 探测失败**时的最后手段；有 password 则**自动静默重登并写新 cookies**，不打断用户去点「重新登录」 |
| 无 password | 无法重登时标记 `need_reauth`，提示补密码或重新导入 |

目标体验：**能自动刷新 cookies 就刷新；尽量少让用户因超时去手动处理；密码重登自动化且少见。**

## 7. 代理

| 类型 | 配置方 |
|------|--------|
| **全局静态代理** | 管理员 / 环境变量 |
| **动态代理池（含 sid）** | **管理员**：URL 模板 `{sid}` + sticky/轮换策略（定时同步抗限流） |
| **账号级代理** | 用户端配置（导入/编辑） |

出站优先级：`账号代理 > 同步任务代理池+sid > 全局静态代理 > 直连`。  
Cookie 账号默认同步 **每账号 sticky sid**。详见 [12](12-trusted-pool-and-mail-sync.md)。

## 7b. 注册用户 · 定时同步 · 我的邮件

| 项 | 决议 |
|----|------|
| 用户体系 | **注册 + 登录**（完整用户体系，非可信密钥） |
| 用户数据 | `owner_user_id` 隔离；用户对本人数据 **完整权限** |
| 默认同步 | 用户私有账号 `sync_enabled=true`；周期默认 **1 小时** |
| 邮件库 | 每用户 **MailIndex**；UI 名「我的邮件」 |
| 谁可搜邮 | **仅登录用户搜自己的** + 管理员运维；**游客禁止（无开关）** |
| 文档 | [12-trusted-pool-and-mail-sync.md](12-trusted-pool-and-mail-sync.md) |

## 8. 限流（两层，消解文档冲突）

| 层级 | MVP | 说明 |
|------|-----|------|
| **运营限流**（配额、管理台、对外产品化 429） | **暂不做** | 保持「先好用」 |
| **工程安全底线** | **必须做** | 防 token 刷爆上游 / Cookie 并发登录 |

工程底线（非可选项）：

1. 收码默认短缓存优先（`refresh=0`）  
2. 同账号取信 **串行**  
3. 同账号 real fetch **最小间隔**（默认数秒，可配）  
4. 批量取信有限并发（如 3）  
5. 代码预留完整限流扩展点  

详见 [10](10-security-review-resolution.md)。

## 9. 技术栈

| 项 | 决议 |
|----|------|

## 10. MVP 范围

- **MVP 要求文档中的功能都包含**（非砍功能版）：  
  多 Provider、双存储、加密、收码 API、游客、管理密码、代理、Cookie 续期、验证码操作，以及 **用户注册登录、私有池上传、hourly 同步、动态 sid 代理、我的邮件搜索**。  
- **第一版**：各邮箱类型 **实号打通**（微软 OAuth、mail.com Cookie、HttpApi/CF、IMAP 一类）。  
- CF Worker：后续可用你提供的 CF 凭证对齐；导入 **兼容 mail-public**。
## 11. 导入格式

- **兼容 mail-public** 为硬需求（`----`、微软四段、api_url 行、client_id/refresh 对调等）。  
- 可额外支持显式前缀与 helper 空白分隔，但不破坏旧格式。

## 12. 隐私表述（与双存储一致）

- 游客可将账号只放在**浏览器**；也可**保存到服务器**（公开号池，实例内他人可见）以便收码 API。  
- 注册用户私有池：`owner_user_id` 隔离；「我的邮件」仅登录用户搜自己的。  
- 服务端保存则加密存储凭证与 cookies；邮件短缓存；用户 hourly 同步写 MailIndex。  
- **无平台代授权**；密钥均来自用户导入。  
- 全文：[07-privacy-and-retention.md](07-privacy-and-retention.md) 与 [legal/](legal/)。

## 13. 明确不做（本阶段）

- 平台托管 OAuth 授权 / 官方应用代用户登录  
- 多管理员 / 多租户  
- Header 式 API Key  
- **运营向**限流/配额产品（工程底线仍要做）  
- 把「未入库账号」签发长期收码 URL（除非先入库）  
- 游客 rotate/delete 收码接口或删除服务端账号（无 current_token / 非管理员）  
- **邀请码注册 / 管理员审批注册**（仅开放注册）  
- **对游客开放「我的邮件」或用户邮件搜索**（无配置开关）
