# 12 · 注册用户体系、定时同步与邮件检索

> **角色**：游客（Guest）· **注册用户（User，原「可信成员」）** · 管理员（Admin）  
> **硬性**：**游客不能搜索、不能访问全站/用户邮件库**。  
> 注册用户经 **注册 + 登录** 使用完整用户体系，对其 **自有数据** 拥有全部权限与功能。  
> 冲突时 **09 + 12 + 10** 优先。

---

## 1. 目标

| 目标 | 说明 |
|------|------|
| 完整用户体系 | 注册、登录、登出、会话、改密；非「贴一个密钥」 |
| 用户自有数据 | 邮箱凭证、同步、邮件索引、收码 API 均带 `owner_user_id` |
| 用户全权限 | 对自己的账号/邮件/API：**增删改查、同步、搜索、导出** 齐全 |
| 定时同步 | 对用户启用同步的账号，默认 **每 1 小时** 自动拉取 |
| 动态代理 | 管理员配置 **带 `{sid}` 的动态代理**（实例级）；用户仍可配账号级代理 |
| 邮件统一视图 | **登录用户**在一个界面看 **自己的** 全部已同步邮件 |
| 检索 | 登录用户在 **自己的 MailIndex** 上按发件人/收件人/主题/正文/时间等搜索 |
| 游客隔离 | 游客 **禁止** 全站/用户邮件搜索与用户邮件库访问 |

## 2. 三角色（定稿）

┌──────────────┐         ┌──────────────┐         ┌──────────────┐
│   管理员     │         │  注册用户    │         │    游客      │
│   Admin      │         │  User        │         │   Guest      │
└──────────────┘         └──────────────┘         └──────────────┘

                           不可见他人用户数据          ✗ 任何用户邮件库

| 能力 | 游客 | 注册用户（本人数据） | 管理员 |
|------|------|----------------------|--------|
| 主操作台、本机浏览器缓存 | ✅ | ✅ | ✅ |
| 公开号池 public（实例共享） | ✅ 可见可用 | ✅ | ✅ |
| 收码 create-or-return（公开号 / 规则内） | ✅ | ✅ | ✅ |
| **注册 / 登录 / 登出** | ❌ | ✅ | 管理端另计 |
| **上传/管理自己的邮箱凭证** | ❌ | ✅ **完整** | ✅（可代管或看全部，见下） |
| **对自己账号的删改、同步开关、导出** | ❌ | ✅ **完整** | ✅ |
| **对自己邮件库搜索**（from/to/subject/body/时间） | **❌ 禁止** | ✅ **完整** | ✅（可查任意用户，运维） |
| **定时同步自己的账号** | ❌ | ✅ | ✅ |
| 实例同步策略、动态 sid 代理池 | ❌ | ❌ | ✅ |
| 用户管理（禁用账号、重置密码） | ❌ | ❌ | ✅ |
| 清库、全局危险操作 | ❌ | ❌ | ✅ |

### 硬性规则

1. **游客永远不能**打开「我的邮件 / 全站邮件」检索，也 **不能** 调用用户邮件搜索 API（返回 401/403）。  
2. **不提供**「对游客开放搜邮」的配置开关。  
3. 注册用户 **只能** 默认访问 `owner_user_id = 自己` 的数据；不能列他人邮箱/邮件。  
4. 管理员可跨用户运维（列表用户、禁用、必要时查看/迁移），须审计日志。

## 3. 用户体系（注册登录）

### 3.1 实体 User

| 字段 | 说明 |
|------|------|
| id | 主键 |
| username / email | 登录名（二选一或都要，实现定） |
| password_hash | 强哈希（argon2/bcrypt） |
| display_name | 可选 |
| status | `active` / `disabled`（开放注册无 `pending` 审批态） |
| role | `user`（注册用户）· 管理员可为独立 Admin 会话，不必占 User 表 |
| created_at / last_login_at | |

### 3.2 注册策略（定稿）

| 模式 | 决议 |
|------|------|
| **开放注册** | **唯一模式**：任意人注册后即 `active`，**无邀请码、无审批** |
| 合规 | 注册时必须勾选同意 **隐私政策** + **使用条款**（未勾选不可提交） |
| 游客 | 可不注册/不登录，继续使用公开取件能力 |

邀请码 / 审批模式 **不做**（本阶段）。

### 3.3 会话

- 登录后 **服务端 Session**（Cookie HttpOnly + Secure）或等价 token。  
- 注册用户 API：`Authorization` 会话 Cookie 即可。  
- 与「游客无会话」「管理员管理密码会话」分离。

### 3.4 用户对自己的完整能力清单

对 `owner_user_id = me` 的数据，注册用户具备：

- 账号：导入、编辑、删除、导出、标签、账号级代理  
- 取信：手动拉取、批量拉取、收件箱/垃圾箱  
- 同步：开启/关闭 `sync_enabled`、查看同步状态、手动「同步我的账号」  
- 邮件：列表、详情、验证码复制、**多字段搜索**  
- 收码 API：对自己账号 create-or-return / rotate / delete（**完整**，不依赖 current_token 绕路）  
- Cookie 会话清除、错误查看  

即：**个人工作区 = 完整产品功能**，不是只读或半套。

## 4. 数据归属与池

```text
┌─ 游客本机缓存 ──────────── 无 owner；不进用户同步
│
├─ 公开号池 public ────────── owner 可空或 system；游客+登录用户可见
│                             收码规则仍按 09/10
│
└─ 用户私有池 user_private ── owner_user_id 必填
                              仅本人（+管理员运维）
                              默认同步 → 写入该用户 MailIndex
                              邮件搜索仅本人
```

| 项 | 决议 |
|----|------|
| 注册用户上传默认池 | `user_private` |
| 用户邮件是否进「别人的搜索」 | **否** |
| 是否还做实例级「所有人共用一个 MailIndex」 | **否**；改为 **每用户 MailIndex**（逻辑隔离，表可带 user_id） |
| 公开号池邮件 | 默认可不入用户索引；若同步 public，索引策略单独定（建议不同步进用户搜邮） |

**「全站邮件」对用户的含义**：该用户名下全部账号的邮件，不是实例上所有人的邮件。  
UI 文案用 **「我的邮件」**，避免误解。

## 5. 定时同步

| 项 | 默认 |
|----|------|
| 周期 | **1 小时**（实例级配置，管理员改） |
| 范围 | 所有 `sync_enabled=true` 且归属清晰的账号（主要是各用户 private） |
| 手动同步 | 用户可「同步我的」；管理员可「同步全部/指定用户」 |
| 并发 | 低；同账号串行；工程底线保留 |
| 代理 | 账号代理 > **实例动态 sid 池** > 全局静态 > 直连 |

```text
every 1h
  for account in sync_enabled:
    proxy = resolve(account)  # 可带 sid
    fetch → upsert MailIndex where user_id = account.owner_user_id
    滚动 cookies / refresh_token
```

---

## 6. 动态代理（sid）

仍为 **管理员配置实例级模板**（与用户体系正交）：

- 模板含 `{sid}`  
- 策略：`sticky_per_account`（Cookie 推荐）/ `rotate_per_sync` / `rotate_on_error`  
- 用户可在自己的账号上覆盖账号级代理

## 7. 邮件搜索（仅登录用户 · 本人数据）

```http
GET /api/me/mails/search
  ?q=&from=&to=&subject=&body=
  &date_from=&date_to=
  &account_id=&folder=&has_code=
```

- 必须登录；强制 `user_id = current_user`。  
- 游客调用 → **403**。  
- 字段：发件人、收件人、主题、正文、时间等。

管理员运维接口可另开：`/api/admin/users/{id}/mails/search`（需管理会话）。

## 9. 与公开号池、收码的关系

| 场景 | 行为 |
|------|------|
| 游客用公开号池 | 不变；可收码 create-or-return（10 权限） |
| 用户自己的号 | 完整权限含 rotate/delete 自己的收码 API |
| 用户是否把号贡献到 public | 可选操作「发布到公开号池」（慎用，需确认） |
| 游客搜用户邮件 | **永不允许** |

---

## 10. 隐私文案（用户体系）

> 游客仅可使用本机缓存与实例公开号池，**不能**搜索或浏览注册用户的邮件。  
> 本实例**开放注册**（无邀请码、无审批）；注册前须同意[隐私政策](legal/privacy.zh.md)与[使用条款](legal/terms.zh.md)。  
> 注册并登录后，您的邮箱凭证与邮件索引仅归您的账户所有；您可完全管理自己的数据。  
> 管理员可管理实例与用户启停，并配置同步代理。

## 12. 决议摘要

1. **完整用户体系**：开放注册 + 登录，不是可信密钥；**无邀请码、无审批**。  
2. **游客禁止**任何用户邮件库与邮件搜索（无开关放开）。  
3. 注册用户对 **本人数据** 拥有 **全部功能权限**。  
4. 邮件索引 **按用户隔离**（我的邮件，非全站混搜）。  
5. 定时 1h + sid 代理 + 加密等既有决议不变。  
6. 管理员负责实例配置与用户启停（无审批队列）。  
7. 注册须勾选同意隐私政策与使用条款（中/英法律页）。

## 13. 废弃表述

以下旧说法作废：

- 「可信密钥粘贴即成员」  
- 「全站邮件对游客可配置开放」  
- 「全局共用 MailIndex 给所有可信成员一起搜」  
- 「邀请码注册 / 管理员审批后才 active」  
- 注册表单中的邀请码字段、管理台「通过审批」「邀请码生成」  

以本文 **User 私有数据 + 开放注册登录** 为准。
